NEURAL GRID MESH

How the AI works.

A readable explanation of the system's design, capabilities, limitations and safety boundaries. This page intentionally documents architecture rather than private credentials, user data or sensitive implementation details.

Does it use a specialized AI framework?

No. Neural Grid MESH is a custom browser runtime written for Re-Ag? using JavaScript, CSS and browser APIs. It does not use TensorFlow.js, PyTorch, ONNX Runtime, Transformers.js or another specialized machine-learning runtime. It does not call a hosted AI API.

The browser's built-in JavaScript engine executes the code. WebAssembly can be added later for measured hot spots, but this release does not require a compiled assembly module.

Five specialist roles

  1. Initiator: schedules tasks, wakes specialists and maps the 3×3 game board into normalized logical coordinates.
  2. Memory Manager: allocates and releases owned 1 KB volume blocks, tracks leases and prevents cross-agent writes.
  3. Learning Agent: maintains a small online neural preference model and local move-frequency profile.
  4. Strategy Agent: uses Minimax with alpha-beta pruning; learned preferences break ties between equally safe moves.
  5. Code Agent: turns a limited set of design instructions into editable HTML, CSS and JavaScript starter code.

Neural map

The current experimental opponent model is a compact 9–16–9 multilayer perceptron:

9 board inputs ↓ 16 tanh hidden units ↓ 9 move preference outputs

It is trained incrementally from moves observed on this device. This is not a 5–6M-parameter general-purpose language model. A random 5–6M network would not become a competent coding assistant without training data and substantial training work.

Memory and caching

  • Working buffers use JavaScript typed arrays and owned 1 KB volume allocations.
  • Persistent learned profiles use local browser storage in this initial release.
  • Cache API is used by the service worker for static app assets, not as RAM.
  • Temporary volume leases are released after specialist tasks.

The browser and iOS control garbage collection, process suspension and cache eviction. The application cannot force the operating system to release physical RAM instantly or guarantee permanent cache retention.

Code Studio boundaries

  • HTML, CSS and JavaScript are previewed in an iframe sandbox without same-origin access.
  • The preview uses a restrictive Content Security Policy with network connections disabled.
  • Saved customizations are local to the current browser profile.
  • Only approved visual theme tokens are applied to the host site.
  • Custom scripts remain in the isolated preview/widget context.

The Code Agent cannot access Supabase credentials, authentication sessions, community posts, moderation, admin roles or database permissions.

Privacy

Game scores, learned move preferences and UI customizations are stored locally in the browser. This AI module does not upload those records to Re-Ag?'s Supabase project. Clearing browser website data can erase local learning and customizations; export options are provided for the UI customization.
